Cross Validation (CV)

Write a brief introduction to cross validation which includes relevant mathematical notation.

Answer: Cross validation is a statistical method used in machine learning to evaluate how well a model performs in an unseen or independent data set. It involves dividing the data set into multiple folds or subsets, using one of these folds as a validation set and training the model on the remaining folds. This process is then repeated multiple times each time using different fold as the validation set. The main purpose of cross validation is to prevent over fitting which occurs when a model is trained too well on the training data and performs poorly on new, unseen data

\(\mathrm{CV}(k) = \frac{1}{k}\sum_{j=1}^k \mathrm{MAE}_j\)

What is the goal of cross-validation? (Hint: Think about over-fitting, along with social/ethical considerations)

Answer: The goal of cross validation is to ensure that a model generalizes well beyond the data on which it was trained by repeatedly holding out different subsets fir testing, it guards against over fitting and produces an approximately unbiased estimate of out of sample error. This process not only helps in selecting and tuning models that truly capture underlying patterns rather than noise, but also promotes robustness and fairness: by validating across different folds.

State which error metric you are using (MAE or MSE) and give its formal mathematical definition. Why did you choose this error metric? What are the advantages/disadvantages of using it?

Answer: I will be using MAE. The formal mathematical definition is:

\(\mathrm{MAE} = \displaystyle\frac{1}{n}\sum_{i=1}^n |y_i - \hat y_i|\)

I chose this error metric because it produces an error metric in the same units as the outcome which makes it immediately interpretable and it is also less sensitive to large outliers than the other error metric like MSE. The main advantage of MAE is the robustness to outliers. Since errors aren’t squared a few extreme misses don’t dominate the metric. Another advantage is that it’s easy to compute and understand which doesn’t require additional transformations.

However, it does have some drawbacks like MAE treats every error the same so one huge miss and several small misses can look equally bad even though we might just care about the big one.

LASSO

Write a brief introduction to LASSO which includes relevant mathematical notation.

Answer: LASSO is a penalized regression method that shrinks coefficient estimates and performs variable selection.

\(\mathrm{RSS} + \lambda \sum_{j=1}^p |\beta_j|\)

where lambda >= 0 is a tuning parameter controlling the strength of the L1 penalty. As lambda grows more coefficients are shrinking towards 0 or exactly to 0 which yields a model that is easier to interpret and often stable in the presence of multicollinearity. LASSO’s key advantages are it’s built in variable selection and improved predictive performance via regularization and it’s main drawback is potential bias in the non-zero coefficients due to shrinkage.

# STEP 1: LASSO Algorithm & Model Specification
# This is copied exactly from the R Code Notes for LASSO Section
lasso_spec <- linear_reg() %>%
  set_mode("regression") %>%
  set_engine("glmnet") %>%
  set_args(mixture = 1, penalty = tune())
# STEP 2: Variable Recipe
variable_recipe <- recipe(gdpgrowth ~ ., data = df_clean) %>%
  step_dummy(all_nominal_predictors())
# STEP 3: Workflow Specification (Model + Recipe)
# This is copied exactly from the R Code Notes for LASSO Section
lasso_workflow <- workflow() %>%
  add_recipe(variable_recipe) %>%
  add_model(lasso_spec)
# STEP 4: Estimate 50 LASSO models using
# lambda values on a "grid" or range from 10^(-5) to 10^(-0.1).
# Calculate the 10-fold CV MAE for each of the 50 models.
set.seed(123)
lasso_models<-lasso_workflow%>%
  tune_grid(
    grid= grid_regular(penalty(range=c(-5,1)),levels= 50 ),
    resamples= vfold_cv(df_clean, v= 10 ),
    metrics= metric_set(mae)
    )
